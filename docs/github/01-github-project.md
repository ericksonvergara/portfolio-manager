# Workflow Oficial

    Orden Estado           Descripción
  ------- ---------------- -----------------------------------------------
        1 📥 Backlog       Trabajo pendiente de planificar
        2 📋 Ready         Listo para comenzar
        3 🚀 In Progress   En desarrollo
        4 👀 Code Review   Pendiente de revisión
        5 🧪 Testing       En pruebas funcionales, integración o QA
        6 ✅ Done          Desarrollo finalizado, validado y documentado

------------------------------------------------------------------------

# Justificación del Workflow

Se definió un flujo de seis estados para separar claramente las etapas
del desarrollo de software.

Las razones principales son:

-   Evitar mover tareas directamente desde desarrollo a producción.
-   Garantizar una revisión de código antes de las pruebas.
-   Asegurar que toda funcionalidad pase por validación antes de
    marcarse como terminada.
-   Mantener una trazabilidad clara del avance del proyecto.

------------------------------------------------------------------------

# Reglas del Workflow

## 📥 Backlog

Contiene todas las historias pendientes de planificación.

## 📋 Ready

Historias completamente refinadas y listas para iniciar.

## 🚀 In Progress

Existe desarrollo activo sobre la historia.

## 👀 Code Review

El desarrollo fue terminado y está pendiente de revisión.

## 🧪 Testing

La historia fue aprobada técnicamente y se encuentra en pruebas.

## ✅ Done

La historia cumple con: - Desarrollo terminado. - Código revisado. -
Pruebas exitosas. - Documentación actualizada. - Lista para formar parte
de una versión.
